# Loans hub (`/loans`)

**Status:** Documented (mobile shell notes)  
**Updated:** 2026-09-21

## Behavior

- **Page header:** Title **Loans** plus scope-specific subtitle from `PAGE_DESCRIPTIONS.loans` via `loan-list-page-config.ts` (updates when scope tab changes).
- **Scope tabs** on `/loans`: **Managing** (default, `?scope=mine`), **Invested**, **Borrowed**, **Witnessed**, **Commissioned**. `/investments`, `/borrowed`, `/commissioned`, `/witnessed` redirect here. **Managing** is loans you operate (`loans.userId`); create and edit stay on this tab. Other tabs are read-only for loan fields, but table/card checkboxes still work for bulk select (add to group, export selected). **Invested**, **Borrowed**, **Witnessed**, and **Commissioned** row/card ⋯ menus add **Add Commission** (`LoanCommissionModal`) plus **Contract Details**.
- Lists loans with search, filters, cards/table/calendar view modes. **Signing** table column (md+): the cell does not open quick view; only the pill is interactive. Red **Pending sign** when the signed-in party still has an unsigned slot (links to `/loans/[id]/sign`). After that party signs, or for viewers with no slot (e.g. loan owner), the pill shows **`signed/total Signed`** (e.g. `1/3 Signed`, `3/3 Signed` green when complete) and opens **Contract Details** when clickable. Em dash only when there are no invitations. Grid cards use the same pills when Contract Details is available. List cache includes `signingInvitations` (`partyRole`, `partyEmail`, `investorId`, `signedAt`, `expiresAt`). Card view footer: **Open** plus a **⋯** menu (same row actions as the table). Canonical loan ⋯ menu (`createLoanActionItems`): Edit, Duplicate | Fund Transfer, Add Received Payment, **Contract Details** | Delete. **Contract Details** opens `LoanContractDetailsModal` (signing status, contract setup tabs, save + download; owners only for edit). Creating a loan also tries to download the contract PDF; a PDF error does not undo the save. When `RESEND_API_KEY` is set, create also emails each investor, borrower, and witness with an address a branded “Contract ready to sign” message (shared shell in `src/lib/server/email/`) with a **Sign contract** link to `/loans/[id]/sign`. Missing emails or Resend config are skipped; email failure does not undo the save.
- **Date range filter** (`from` / `to` URL params, `YYYY-MM-DD`, or `?range=all` for all-time): filters loans by **due date** (inclusive). Presets: week, month, year, all-time, custom. **Default:** current calendar month — `+page.server.ts` redirects to `?from=` / `?to=` when missing; list + summary cards filter from picker state (URL stays in sync via `replaceState`). Changing the range updates the URL with `replaceState` (not `goto`) and does **not** reload the loan query. All-time clears `from` / `to` and shows every loan; summary cards use full history. Group hub lists default to all-time and set `?range=all` on first load when params are missing. Prev/next navigates the active preset (not all-time or custom). Clear resets to the scope default (month on Managing, Invested, Borrowed, Witnessed, and Commissioned; all-time on group hub). **Invested** and **Borrowed** show principal/interest summary cards only. **Commissioned** lists the union of all party loans and shows commission summary cards (`computePartyCommissionStats`) from the date-filtered list. Legacy `?dueDate=` (exact day from calendar links) still works alongside the range.
- **Summary cards** (below header when the list has data): **Principal** (outstanding paid principal on open loans in the due-date-filtered list), **Total** (principal + scheduled interest estimate on loans in the range), **Interest** (`earned / estimate` compact pair: completed-loan interest / all scheduled interest in the range), and **Completed** (`completed / total` loan count). Card metrics use the date range only (ignore search/status/type filters). Unpaid disbursements are excluded from principal.
- **Phone (`<lg`):** card/row open navigates to `/loans/[id]` via `isMobileShellViewport()`. Row/card ⋯ menus use `ResponsiveOverflowMenu` (bottom sheet, not a floating dropdown). New loan and row edit open a bottom sheet (`LoanCreateModal` / `LoanDetailModal` in edit mode), not `/loans/new`. Create / quick-pay / export / detail quick-view use `ResponsiveModal` (presentation locked while open; sheet under `lg`). Overlays open immediately on tap; investors/borrowers/witnesses for create/edit and More Filters share one prefetch (`party-options` + `use-loan-form-options`); the shell shows first, then `FormPageSkeleton` while options or the lazy `LoanForm` chunk load. Fund Transfer, Contract Details, and Duplicate open with list-row data and refresh in the background when needed. Sheet form title stays in the header; Cancel / submit sit in the scrolling form (`FormActions`, primary on top). `PageHeader` title sits in content below the brand bar. PageHeader actions (export, new loan) render in MobileTopBar as frosted icon wells. Search + filters share one row (`.mobile-list-toolbar`). View toggle stays in the toolbar on phone. Calendar view defaults to day view under `lg`. Phone calendar chrome is a compact day toolbar (title + Today/prev/next; no Day-only toggle). Week/month stay `lg+`. Calendar **cells** omit type/status/signing pills (`showHeaderBadges={false}` on `Loan*EventCard`). The **Events for …** day modal uses `eventCardModal` with group chip (or **Ungrouped**), type, status, and signing pills (`showGroupBadges` + `showHeaderBadges`). List pagination (`Pagination` / `CardPagination`) is a compact footer: range + page-size on one row, prev / current of total / next on the next. Page number pills stay `lg+`.
- **Toolbar:** Search and view toggle on one row. **Date range** sits in the **page header** on desktop (`lg+`, next to Export / New Loan) with prev/next for week, month, and year. On phone it is a full-width row under scope tabs (not beside search). **More Filters** holds **Group** (when groups exist), **Status**, **Type**, principal/rate/interest/total amount ranges, and searchable investor/borrower/witness multi-selects (including **Unassigned**). Group / Status / Type stack on phone, sit two-up from `sm`, and share one row from `lg` when Group is present (selects are full-width in the grid). Active advanced filters (group, status, type, amounts, participants) show a dot on More Filters.
- **Desktop (`lg+`):** floating sidebar; row click and calendar event cards open `LoanDetailModal` in view mode (same `handleQuickView` path as the table). The modal header uses list-row data immediately; the detail body loads after the dialog paints (lazy chunk + tick/double-rAF defer), then refreshes `GET /api/loans/[id]` in the background. Light `ResponsiveModal` overlays (pickers, confirms, New group) mount the body immediately. Heavy loan create/detail still defer internally. Contract Details paints its shell immediately, then loads the editor from `$effect` into `$state` (never `{#await import()}` in the modal body). Dialog panels do not fade in. While an overlay is open, `html.overlay-open` uses a solid scrim with no backdrop blur. On **`lg+`**, it also skips painting the list (`.app-shell`); mobile sheets keep list content visible under the scrim. Month-view **+N more** opens the day events overlay; choosing a loan from that overlay stacks `LoanDetailModal` on top and leaves the events overlay open behind it. **Edit** from the row ⋯ menu opens `LoanDetailModal` in edit mode (`startInEditMode`), not `/loans/[id]`. Search, filters, and the loans table sit on white card surfaces (`bg-card` / `.surface-card`) matching dashboard cards. Week/month calendar grids are fluid (seven equal columns, no horizontal scroll); event cards and daily totals truncate on narrow desktop widths beside the sidebar. Calendar and row-action dropdowns use the shared menu primitive (`min-w` 15rem, `min-h-11` items, labels do not wrap). `ResponsiveModal` (`responsive-modal-shell`) keeps a fixed header and footer; only the body scrolls. Quick-view: title left (`text-base font-medium`), `DetailModalHeader` actions top-right. Create / edit loan: `FormHeader` (`variant="embedded"`) in the fixed header with Cancel / submit wired via `form` attribute; form fields scroll below. Shell padding is `0` (header uses `px-5 md:px-6` / `pt-6 pb-4`, body uses `px-5 py-4 md:px-6 md:py-5`). Create Loan modal is `max-w-4xl` with no extra close X; Cancel / submit live only in the fixed header (no duplicate footer actions in the scroll body). Nested form card titles use the default `text-base font-medium`. Inputs and selects are `h-11` / `rounded-2xl` with `bg-card`. Subtitle is `Manage all your loans`. Visual layout is asserted by `e2e/visual-parity.spec.ts`.
- Save, complete, quick-pay, and delete patch that loan in the in-memory list (`applyLoanListChange` in `src/lib/composables/refresh-loan-list.ts`). They do not `invalidate('app:loans')`. Creating a loan still reloads the list. Recording received payments that cover the total due sets status to `Completed` (not Overdue). Fund Transfer can add another principal disbursement for the same lender on the same sent date.
- **Owner (lender):** lists loans where `loans.userId` matches the signed-in user. New Loan and row edit/delete when the user owns the loan (`hasLoanAdminAccess`).
- **Party users:** same page when they have group or party read access; create/edit/delete only for owned loans.
- **Groups (when `SHOW_GROUPS_UI`):** **Group** filter in **More Filters** filters by `?group=` (including Ungrouped). Grid cards: loan title on its own row; group badge (or **Ungrouped** pill) plus type/status/signing pills wrap on the row below (tap group chip to filter). Card height stays aligned via the shared meta row. All scope tabs get bulk select + `LoanBulkActionBar` (checkboxes in the table; **Select** on phone). On phone, **Select** collapses the list toolbar to search + **Done**; the bulk bar replaces the tab dock (one bottom layer) until the selection is cleared. **Summary** opens a light `ResponsiveModal` (`LoanSelectionSummaryModal`) with the same Principal / Interest (or Commission) cards as the page, computed from the checked rows (`computeLoanListSummaryStats` / `computePartyCommissionStats`, same due-date range as the list). Add to group still requires loan ownership (`hasLoanAdminAccess`). Shared UI: `LoanListPage` + `use-loan-list-group-scope`. Group hub Loans tab uses `scope="group"` (no group filter; date range on the toolbar row after search; defaults to all-time; members stay view-only).
- **Loading:** `ListPageSkeleton` mirrors the loaded chrome: header, 4 summary metric cards, search/filter toolbar on a card surface, and a table card with identity cells (avatar + name) plus pagination.
