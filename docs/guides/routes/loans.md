# Loans hub (`/loans`)

**Status:** Documented (mobile shell notes)  
**Updated:** 2026-09-21

## Behavior

- **Page header:** Title **Loans** plus scope-specific subtitle from `PAGE_DESCRIPTIONS.loans` via `loan-list-page-config.ts` (updates when scope tab changes).
- **Scope tabs** on `/loans`: **Managing** (default, `?scope=mine`), **Invested**, **Borrowed**, **Witnessed**, **Commissioned**. `/investments`, `/borrowed`, `/commissioned`, `/witnessed` redirect here. **Managing** is loans you operate (`loans.userId`); create and edit stay on this tab. Other tabs are read-only for loan fields, but table/card checkboxes still work for bulk select (add to group, export selected). **Invested**, **Borrowed**, **Witnessed**, and **Commissioned** row/card ⋯ menus add **Add Commission** (`LoanCommissionModal`) plus **Contract Details**.
- Lists loans with search, filters, cards/table/calendar/timeline view modes. **Signing** table column (md+): the cell does not open quick view; only the pill is interactive. Red **Pending sign** when the signed-in party still has an unsigned slot (links to `/loans/[id]/sign`). After that party signs, or for viewers with no slot (e.g. loan owner), the pill shows **`signed/total Signed`** (e.g. `1/3 Signed`, `3/3 Signed` green when complete) and opens **Contract Details** when clickable. Em dash only when there are no invitations. Grid cards use the same pills when Contract Details is available. List cache includes `signingInvitations` (`partyRole`, `partyEmail`, `investorId`, `signedAt`, `expiresAt`). Card view: tap the card to open (navigate on phone, quick-view modal on desktop); **⋯** top-right (same row actions as the table). Bulk **Select** on phone toggles the checkbox on card tap. No footer **Open** button. Canonical loan ⋯ menu (`createLoanActionItems`): Edit, Duplicate | Fund Transfer, Add Received Payment, **Contract Details** | Delete. **Contract Details** opens `LoanContractDetailsModal` (signing status, contract setup tabs, save + download; owners only for edit). Creating a loan also tries to download the contract PDF; a PDF error does not undo the save. When `RESEND_API_KEY` is set, create also emails each investor, borrower, and witness with an address a branded “Contract ready to sign” message (shared shell in `src/lib/server/email/`) with a **Sign contract** link to `/loans/[id]/sign`. Missing emails or Resend config are skipped; email failure does not undo the save.
- **Date range filter** (`from` / `to` URL params, `YYYY-MM-DD`, or `?range=all` for all-time): filters loans by **due date** (inclusive). Presets: week, month, year, all-time, custom. **Default:** current month. A chosen range is remembered in this browser (loan lists share one saved range; the group hub remembers its own). Opening Loans, Invested, Borrowed, Witnessed, or Commissioned without dates restores that saved range, otherwise the current month. An explicit `from`/`to` or `range=all` link still wins. `+page.server.ts` redirects when dates are missing. List + summary cards filter from picker state (URL stays in sync via `replaceState`). Changing the range updates the URL with `replaceState` (not `goto`) and does **not** reload the loan query. All-time clears `from` / `to` and shows every loan; summary cards use full history. Group hub lists default to the current month, the same as the loan lists, and remember their own range. Prev/next navigates the active preset (not all-time or custom). Clear resets to the current month on Managing, Invested, Borrowed, Witnessed, Commissioned, and the group hub, and remembers that. **Invested** and **Borrowed** show principal/interest summary cards only. **Commissioned** lists the union of all party loans and shows commission summary cards (`computePartyCommissionStats`) from the date-filtered list. Legacy `?dueDate=` (exact day from calendar links) still works alongside the range.
- **Timeline:** day-by-day cashflow for the loans already on the page (search, status, type, amounts, participants, group, and the selected due-date range). Money out is **Sent**, or **Scheduled** when a disbursement is still unpaid. Money in is **Interest** or **Due**. Each movement shows the loan status badge beside the loan name. Only days with activity are listed, except **today** when it falls in the selected range (or between the first and last event on all-time): that day still appears with a single **No activity** card row when nothing moved. Month headers stick under the phone brand bar: month name left, **In** / **Out** on one right-aligned row (**Net** only when both directions have activity that month). A day with more than one movement shows the same row in a footer below that day's movements inside the card. There is no range-level total and no in/out bar chart. Opening a single-month range stays at the top. A range that covers more than the current month scrolls that month into view. A floating card-surface **Today** pill (soft primary-tinted arrow well pointing up/down toward today) appears while that day is off screen. Tap a row to open the loan (detail route on phone, quick view on desktop). `?view=timeline` selects it. The same toggle is on Managing, Invested, Borrowed, Witnessed, Commissioned, and the group hub Loans tab. Investors, borrowers, witnesses, and bank loans stay cards/table.
- **Summary cards** (below header when the list has data): **Principal** (outstanding paid principal on open loans in the due-date-filtered list), **Total** (principal + scheduled interest estimate on loans in the range), **Interest** (`earned / estimate` compact pair: completed-loan interest / all scheduled interest in the range), and **Completed** (`completed / total` loan count). Card metrics use the date range only (ignore search/status/type filters). Unpaid disbursements are excluded from principal.
- **Phone (`<lg`):** card/row open navigates to `/loans/[id]` via `isMobileShellViewport()`. Row/card ⋯ menus use `ResponsiveOverflowMenu` (bottom sheet, not a floating dropdown). New loan and row edit open a bottom sheet (`LoanCreateModal` / `LoanDetailModal` in edit mode), not `/loans/new`. Create / quick-pay / export / detail quick-view use `ResponsiveModal` (presentation locked while open; sheet under `lg`). Overlays open immediately on tap; investors/borrowers/witnesses for create/edit and More Filters share one prefetch (`party-options` + `use-loan-form-options`); the shell shows first, then `FormPageSkeleton` while party options, `GET /api/loans/[id]` detail (edit mode), or the lazy `LoanForm` chunk load. Fund Transfer, Contract Details, and Duplicate open with list-row data and refresh in the background when needed. Sheet form title stays in the header; Cancel / submit sit in the scrolling form (`FormActions`, primary on top). `PageHeader` title sits in content below the brand bar. PageHeader actions (export, new loan) render in MobileTopBar as frosted icon wells. Search + **More Filters** (and **Select** when bulk mode is on) use `.mobile-list-toolbar`. View toggle on phone is cards + timeline (timeline is the default on `<lg`; tapping **Select** switches to cards so checkboxes show); table and in-app **calendar** are `lg+` (week/month calendar chrome and calendar day toolbar match desktop calendar docs). Calendar **cells** show the loan status badge beside the loan name (`LoanStatusBadge`; type, group, and signing stay off the cell). The **Events for …** day modal uses `eventCardModal` with group chip (or **Ungrouped**), type, status, and signing pills (`showGroupBadges` + `showHeaderBadges`). List pagination (`Pagination` / `CardPagination`): segmented **Page X of Y** with prev/next, then one meta row (`1–9 of 80` and **9 / page** sheet). Page number pills stay `lg+`.
- **Toolbar:** Search on one row with **More Filters** (and **Select** when bulk mode is available) on phone; **view toggle** on phone is **cards** and **timeline** only (table and calendar segments are `lg+`). `?view=calendar` on a narrow viewport opens **timeline** instead. **Date range** sits in the **page header** on desktop (`lg+`, next to Export / New Loan) with prev/next for week, month, and year. On phone it is a full-width row under scope tabs (not beside search). **More Filters** on phone opens a bottom sheet (`MoreFiltersSurface` + `ResponsiveModal`); on `lg+` the same fields expand inline under the toolbar. The panel holds **Group** (when groups exist), **Status**, **Type**, principal/rate/interest/total amount ranges, and searchable investor/borrower/witness multi-selects (including **Unassigned**). Group / Status / Type stack in the sheet on phone, sit two-up from `sm`, and share one row from `lg` when Group is present (selects are full-width in the grid). Active advanced filters (group, status, type, amounts, participants) show a dot on More Filters.
- **Desktop (`lg+`):** floating sidebar; row click and calendar event cards open `LoanDetailModal` in view mode (same `handleQuickView` path as the table). The modal header uses list-row data immediately; the detail body loads after the dialog paints (lazy chunk + tick/double-rAF defer), then refreshes `GET /api/loans/[id]` in the background. Light `ResponsiveModal` overlays (pickers, confirms, New group) mount the body immediately. Heavy loan create/detail still defer internally. Contract Details paints its shell immediately, then loads the editor from `$effect` into `$state` (never `{#await import()}` in the modal body). Dialog panels do not fade in. While an overlay is open, `html.overlay-open` uses a solid scrim with no backdrop blur. Desktop dialogs and mobile sheets keep the list visible and dimmed under the scrim. Month-view **+N more** opens the day events overlay; choosing a loan from that overlay stacks `LoanDetailModal` on top and leaves the events overlay open behind it. **Edit** from the row ⋯ menu opens `LoanDetailModal` in edit mode (`startInEditMode`), not `/loans/[id]`. Search, filters, and the loans table sit on white card surfaces (`bg-card` / `.surface-card`) matching dashboard cards. Week/month calendar grids are fluid (seven equal columns, no horizontal scroll); event cards and daily totals truncate on narrow desktop widths beside the sidebar. Calendar and row-action dropdowns use the shared menu primitive (`min-w` 15rem, `min-h-11` items, labels do not wrap). `ResponsiveModal` (`responsive-modal-shell`) keeps a fixed header and footer; only the body scrolls. Quick-view: title left (`text-base font-medium`), `DetailModalHeader` actions top-right. Create / edit loan: `FormHeader` (`variant="embedded"`) in the fixed header with Cancel / submit wired via `form` attribute; form fields scroll below. Shell padding is `0` (header uses `px-5 md:px-6` / `pt-6 pb-4`, body uses `px-5 py-4 md:px-6 md:py-5`). Create Loan modal is `max-w-4xl` with no extra close X; Cancel / submit live only in the fixed header (no duplicate footer actions in the scroll body). Nested form card titles use the default `text-base font-medium`. Inputs and selects are `h-11` / `rounded-2xl` with `bg-card`. Subtitle is `Manage all your loans`. Visual layout is asserted by `e2e/visual-parity.spec.ts`.
- Save, complete, quick-pay, and delete patch that loan in the in-memory list (`applyLoanListChange` in `src/lib/composables/refresh-loan-list.ts`). They do not `invalidate('app:loans')`. Creating a loan still reloads the list. Recording received payments that cover the total due sets status to `Completed` (not Overdue). Fund Transfer can add another principal disbursement for the same lender on the same sent date. Fund Transfer, Add Received Payment, and loan-form disbursement rows open with the fields visible. The receipt image is required on save, not before the fields can be filled. Saving without a required receipt scrolls to that upload, marks it, and disables Create or Update until a receipt is attached. A scan that is not a receipt (a chat screenshot, a note, an unrelated photo) still keeps the image on that row and shows a warning. It does not add an empty transaction or block save. A chat that states an amount is read as a transfer. Each of those rows, and each principal disbursement or received payment on the loan form, has an optional Notes field (up to 2000 characters). Notes are stored on that disbursement or payment and shown on the loan detail. New loans require a receipt on each principal disbursement and on each received payment that has an amount. The standalone Create Transaction form already has optional Notes.
- **Owner (lender):** lists loans where `loans.userId` matches the signed-in user. New Loan and row edit/delete when the user owns the loan (`hasLoanAdminAccess`).
- **Party users:** same page when they have group or party read access; create/edit/delete only for owned loans.
- **Templates:** when the signed-in user has saved loan templates, **New Loan** opens a menu (bottom sheet on phone, dropdown on desktop): **Blank loan**, then each template. Choosing a template opens Create Loan with that preset already applied. The form still shows **Template** at the top of Loan Details so it can be changed. Choosing one fills type, groups, rate, notes, and the loan name. When the template has borrowers, those switches replace the borrower dropdown in the same column beside Loan name. A loan still has one borrower, so turning one on turns the others off. The first borrower starts on. Unchecking the selected borrower hides the switches and shows the borrower dropdown. Template investors appear as switches at the top of Investors, each with its saved rate, and all start on. Turning one off removes that investor card. Amount, receipt, and sent date stay on the form. Those fields stay editable. `{sent}` and `{due}` in the template name stay in sync with the sent date and due date until the name is edited. Due in days moves the due date forward from today (new templates start at 14 days). Receipt upload still fills the amount. Edit and duplicate hide the picker. Templates are managed on Settings and are not seeded.
- **Groups (when `SHOW_GROUPS_UI`):** **Group** filter in **More Filters** filters by `?group=` (including Ungrouped). Grid cards: loan title on its own row; group badge (or **Ungrouped** pill) plus type/status/signing pills wrap on the row below (tap group chip to filter). Card height stays aligned via the shared meta row. All scope tabs get bulk select + `LoanBulkActionBar` (checkboxes in the table; **Select** on phone). On phone, **Select** toggles card checkboxes; the list toolbar stays visible (**Done** replaces **Select** in the action row). The bulk bar replaces the tab dock (one bottom layer) until the selection is cleared. **Summary** opens a light `ResponsiveModal` (`LoanSelectionSummaryModal`) with the same Principal / Interest (or Commission) cards as the page, computed from the checked rows (`computeLoanListSummaryStats` / `computePartyCommissionStats`, same due-date range as the list). Add to group still requires loan ownership (`hasLoanAdminAccess`). Shared UI: `LoanListPage` + `use-loan-list-group-scope`. Group hub Loans tab uses `scope="group"` (no group filter; date range on the toolbar row after search; defaults to all-time; members stay view-only).
- **Loading:** `ListPageSkeleton` mirrors the loaded chrome: header, 4 summary metric cards, search/filter toolbar on a card surface, and a table card with identity cells (avatar + name) plus pagination.
