# Group hub (`/groups/[id]`)

**Status:** Documented (Loan Groups v2)
**Updated:** 2026-10-27

## Behavior

Hub for one group. Tabs via `?tab=`: **Overview · Loans · People · Settings** (Settings is owner-only).

- **Header:** back link, title, color dot; meta line (`N loans · N people · Next due …`) with viewer role pill (**Owner** or party roles) on the same row; optional notes below. Owner actions (**Add loans** with plus icon, Settings/Delete overflow) top-right on desktop; on phone both actions sit in the brand hero bar (`GroupHubHeader.svelte`)
- **Overview:** loan summary cards (Principal, Total, Interest, Completed). Each card has an **About** control (hover on a fine pointer, tap on touch) that explains the figure for loans in this group. The group creator always sees Interest. Borrowers, witnesses, and other investors see it only when the creator turns that role on under Settings. When Interest is hidden, the other three cards use two columns below `lg` (the last card spans the row) and three equal columns from `lg`. Needs-attention (overdue; **View loans** opens the Loans tab with `status=Overdue` and a due-date range that includes every overdue loan in the banner), then **Group** (description/notes), **Channels** (calendar + Telegram status: Not connected / Not set up / Connected / Needs attention; no helper line), **Upcoming** (next open loans by due date)
- **Loans:** same list chrome as `/loans` (`LoanListPage` `scope="group"`), including the **Total Amount** column and card cell (principal plus scheduled interest). **Phone:** full-width date range directly under hub tabs and above summary cards (defaults to the current month, the same as `/loans`; a chosen range is remembered on this hub and does not change the loan lists; **Clear** returns to the current month). Then summary cards (Interest follows the same Settings toggles as Overview; the Total Interest filter is hidden with that card), then a stacked toolbar (full-width search, then a left-aligned row: view toggle / **More Filters** (bottom sheet) / **Select**). **Export PDF** sits in the group hub header beside **Add loans** (desktop and mobile brand bar), not in the list toolbar. View toggle on phone is cards and timeline (timeline is the default; **Select** switches to cards); calendar and table are `lg+`. Timeline lists in/out by day inside the selected range. **Desktop:** summary cards first, then toolbar with inline date range beside search. Search, status/type/more filters, export, and pagination match `/loans`. On phone, **Select** toggles card checkboxes; the toolbar stays the same (**Done** replaces **Select** in the action row). The bulk bar replaces the tab dock. Bulk bar **Summary** opens the same selection stats modal as `/loans`. Owner can **Add loans** (picker + access preview), **Remove from group** (row ⋯ and bulk), and still edit/delete owned loans. Members are view-only.
- **People:** role-grouped roster (`GroupPeopleTab.svelte`); no access banner. Each role is one list with a count. Closed rows are one vertically centered line: name, extra roles (not the section's own), principal or capital, interest, and loan count. Interest on the row, and interest totals inside an expanded person, follow the same Settings toggles as the overview Interest card. Phone hides the amount labels and truncates the name. Expanding a row reuses investor detail (`InvestorDetailContent`, no header or Bank Loans tab) scoped to that person's loans in this group. The **Total Amount** column is that investor's principal plus interest, or the full loan total for owner, borrower, and witness rows. Summary cards stay on principal with the same scoping. Emails stay stripped from SSR and `GET /api/groups/[id]` for non-managers.
- **Settings:** name/color/description, **Interest card** (creator only; checkboxes for Borrowers, Witnesses, and Other investors; off by default; saves immediately; the creator always sees the card; a member with more than one of those roles sees it only when every held role is on), **Auto-add loans** (each rule is separate; a new loan you own is added when any rule matches an investor or borrower on that loan), **Default witnesses** (up to two; the same person from several groups is added once; **Auto-sign** records a saved signature on new and edited loans in the group), **Google Calendar** card (batched sync via `POST /api/groups/[id]/calendar/sync`, subscribe link). **Clear events** deletes every event on that group's Google calendar in batches (orphans, duplicate copies, and Total Summary rows), not only current loans. Run Clear on each group calendar you subscribe to if duplicates span groups. Telegram card (per-group bot token + chat ID connect, optional env `startgroup` link, notifications switch plus grouped Reminders / Updates lists). Reminders include lead-time chips for upcoming dues, and **Unsigned contracts**: how often (1 hour through daily, default every hour) and who must sign (Borrower and Investor on, Witness off). Message templates in four categories (Reminders, Digests, Activity, Other). One template at a time, with Edit/Preview, highlighted `{{placeholders}}`, a grouped insert sheet, and reset. Defaults name the loan, type, status, borrower, investors, due date, principal, and the event amount. Activity templates cover new loan, added, updated, disbursement, payment, interest extended, completed, removed, and contract signed. The bot command `/upcoming` uses the Next 7 days template. Show amounts off prints Hidden. Phone, email, address, and bank details are not placeholders. Optional lines use `{{#if key}}`., test/disconnect, delete. Card actions use `groupSettingsActionClass` (full width below `lg`, auto width on desktop) and `groupSettingsActionsLayoutClass` for button rows; one primary action per card where needed (e.g. **Save**, **Connect**, **Create calendar**), secondary actions **outline**. **Disconnect** / **Delete group** stay destructive. After a successful general save, client calls `invalidate('app:groups')`; load uses `depends('app:groups')` in `+page.server.ts`
- Owner can **Add loans** from the hub header or Loans tab (picker + access preview). Add-loan picker and rule contact lists load from `GET /api/groups/[id]/addable-loans` when the sheet or **Add rule** modal opens.

## Load

`+page.server.ts` loads group metadata (members, rules, channels) and group loans via `getCachedLoansByIds` (list relations, 45s process cache; cleared with `invalidateGroupData` / `invalidateLoanData`). No full owned-loan scan on initial hub load.

Membership is recomputed on loan/party writes (`recomputeGroupMembers`), not on page load. Access preview on a group requires manage access. Creating a Telegram link invalidates prior unused tokens for that group.

## Access

`hasGroupViewAccess` / `hasGroupManageAccess` in `src/lib/server/group-access.ts`. Group loan detail uses `hasLoanGroupViewAccess` + `projectLoanForGroupViewer` (PII redacted). Payment/contract/storage endpoints still require party `hasLoanViewAccess`.

## Integrations

- Google Calendar: provisioned per group via jobs (`group.calendar.*`); subscribe URL for members
- Default witnesses: `GET/PUT /api/groups/[id]/default-witnesses` (owner saves; a contract holds two). Loan create, loan edit, `PUT /api/loans/[id]/groups`, and adding loans from the group apply them. Empty witness slots are filled. Occupied slots that name someone else stay. **Auto-sign** sets the invitation signed when that witness has a saved signature, and those witnesses are left off the new-loan signing email.
- Telegram: `POST /api/groups/[id]/telegram/connect` (verify `getMe` + `getChat`, store chat; optional per-group `bot_token`), `GET/PUT/DELETE /api/groups/[id]/telegram` (toggles + merged `templates`; unknown kinds, templates over 4,000 characters, and tags other than `b`, `i`, `u`, `s`, `a`, `code`, `pre`, `br` are rejected; never returns raw token, only `botTokenConfigured`), optional env `startgroup` link (`POST …/telegram/link` when `TELEGRAM_BOT_*` + webhook secret set); webhook `POST /api/webhooks/telegram` (`/upcoming` renders the Next 7 days template); daily due reminders and digest on `/api/cron/groups`; unsigned-contract reminders on `/api/cron/signing-reminders` (daily at 00:00 UTC, each group still sends only on its interval). Loan create, update, disbursement, received payment, interest extension, completion, add to group, remove from group, and a manual contract signature enqueue an activity message. Auto-sign does not.
